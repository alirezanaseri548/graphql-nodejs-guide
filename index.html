راهنمای حرفه‌ای GraphQL + Node.js

GraphQL چیست و چگونه در Node.js از آن استفاده کنیم؟

این سند یک نمای علمی، مهندسی و عملی از GraphQL ارائه می‌دهد؛ از مفاهیم بنیادی و تفاوت آن با REST گرفته تا طراحی Schema، Resolverها، اتصال به دیتابیس، امنیت، Performance و پیاده‌سازی در Node.js.

1) مقدمه

GraphQL یک زبان پرس‌وجو برای API و یک runtime برای اجرای آن روی داده‌های تایپ‌شده است. در GraphQL، کل قرارداد داده از طریق یک Schema مشخص می‌شود. این Schema تعیین می‌کند که چه داده‌ای قابل درخواست است، چه نوعی دارد و چه عملیات‌هایی روی آن انجام می‌شود.

ایده اصلی GraphQL این است که کلاینت دقیقاً همان داده‌ای را بگیرد که نیاز دارد؛ نه کمتر و نه بیشتر.

2) تفاوت REST و GraphQL

REST

  • چند endpoint مجزا دارد
  • ساختار پاسخ را معمولاً سرور تعیین می‌کند
  • گاهی با over-fetching و under-fetching مواجه می‌شود
  • نسخه‌بندی API معمولاً رایج‌تر است

GraphQL

  • معمولاً یک endpoint واحد مثل /graphql دارد
  • کلاینت ساختار داده مورد نیاز را مشخص می‌کند
  • انعطاف‌پذیری بالاتر در دریافت داده
  • Schema تایپ‌شده و self-documenting
معیار REST GraphQL
تعداد endpoint چندین endpoint اغلب یک endpoint
انعطاف در انتخاب فیلد کمتر بسیار بالا
مستندسازی جداگانه یا Swagger/OpenAPI بخشی از Schema
کنترل ساختار پاسخ سرورمحور کلاینت‌محور

3) مفاهیم اصلی GraphQL

Type

تعریف ساختار داده، مثل User یا Post.

Query

برای خواندن داده استفاده می‌شود.

Mutation

برای ایجاد، ویرایش یا حذف داده استفاده می‌شود.

Resolver

تابعی که داده نهایی هر فیلد یا عملیات را برمی‌گرداند.

Schema

قرارداد رسمی و تایپ‌شده API.

Subscription

برای دریافت داده به‌صورت real-time.

مثال ساده Query

query {
  users {
    id
    name
    email
  }
}

پاسخ

{
  "data": {
    "users": [
      { "id": "1", "name": "Ali", "email": "ali@example.com" }
    ]
  }
}

4) طراحی Schema

کیفیت یک سیستم GraphQL تا حد زیادی به طراحی درست Schema وابسته است. Schema خوب باید:

  • معنادار و domain-oriented باشد
  • فیلدها نام‌گذاری شفاف داشته باشند
  • روابط بین موجودیت‌ها واضح باشند
  • تا حد ممکن پایدار و قابل توسعه باشد

نمونه Schema

type User {
  id: ID!
  name: String!
  email: String!
  posts: [Post!]!
}

type Post {
  id: ID!
  title: String!
  content: String
  author: User!
}

type Query {
  users: [User!]!
  user(id: ID!): User
  posts: [Post!]!
}

type Mutation {
  createUser(name: String!, email: String!): User!
  createPost(title: String!, content: String, authorId: ID!): Post!
}
طراحی Schema نباید صرفاً کپی مستقیم ساختار دیتابیس باشد. Schema باید بر اساس نیاز مصرف‌کننده API و مدل دامنه طراحی شود، نه فقط جدول‌های دیتابیس.

5) ارتباط GraphQL با Node.js

Node.js یکی از متداول‌ترین بسترها برای ساخت GraphQL server است. دلیل آن:

  • اکوسیستم قوی جاوااسکریپت و تایپ‌اسکریپت
  • وجود کتابخانه‌های بالغ مثل Apollo Server و GraphQL Yoga
  • هماهنگی بالا با فرانت‌اندهای مدرن مثل React، Next.js و Vue
  • سادگی در نوشتن resolverها و اتصال به سرویس‌ها و دیتابیس‌ها

فلو اجرا در Node.js

  1. کلاینت یک Query یا Mutation می‌فرستد
  2. GraphQL server درخواست را با Schema اعتبارسنجی می‌کند
  3. Resolver مربوطه اجرا می‌شود
  4. Resolver به دیتابیس یا سرویس دیگر متصل می‌شود
  5. پاسخ نهایی طبق ساختار requested fields برگردانده می‌شود

6) نمونه پروژه عملی در Node.js

نصب پکیج‌ها

npm init -y
npm install @apollo/server graphql express cors body-parser
npm install @as-integrations/express5

نمونه فایل سرور

import express from "express";
import cors from "cors";
import bodyParser from "body-parser";
import { ApolloServer } from "@apollo/server";
import { expressMiddleware } from "@as-integrations/express5";

const users = [
  { id: "1", name: "Ali", email: "ali@example.com" },
  { id: "2", name: "Sara", email: "sara@example.com" }
];

const posts = [
  { id: "1", title: "GraphQL Intro", content: "Hello GraphQL", authorId: "1" }
];

const typeDefs = `#graphql
  type User {
    id: ID!
    name: String!
    email: String!
    posts: [Post!]!
  }

  type Post {
    id: ID!
    title: String!
    content: String
    author: User!
  }

  type Query {
    users: [User!]!
    user(id: ID!): User
    posts: [Post!]!
  }

  type Mutation {
    createUser(name: String!, email: String!): User!
    createPost(title: String!, content: String, authorId: ID!): Post!
  }
`;

const resolvers = {
  Query: {
    users: () => users,
    user: (_, { id }) => users.find(user => user.id === id),
    posts: () => posts
  },
  Mutation: {
    createUser: (_, { name, email }) => {
      const newUser = {
        id: String(users.length + 1),
        name,
        email
      };
      users.push(newUser);
      return newUser;
    },
    createPost: (_, { title, content, authorId }) => {
      const newPost = {
        id: String(posts.length + 1),
        title,
        content,
        authorId
      };
      posts.push(newPost);
      return newPost;
    }
  },
  User: {
    posts: (parent) => posts.filter(post => post.authorId === parent.id)
  },
  Post: {
    author: (parent) => users.find(user => user.id === parent.authorId)
  }
};

const server = new ApolloServer({
  typeDefs,
  resolvers
});

await server.start();

const app = express();
app.use("/graphql", cors(), bodyParser.json(), expressMiddleware(server));

app.listen(4000, () => {
  console.log("Server running at http://localhost:4000/graphql");
});

نمونه Query

query {
  users {
    id
    name
    posts {
      title
    }
  }
}

نمونه Mutation

mutation {
  createUser(name: "Reza", email: "reza@example.com") {
    id
    name
    email
  }
}

7) Best Practices

1. Schema-first Design

ابتدا Schema را طراحی کن، سپس resolver و دیتابیس را با آن هماهنگ کن. این روش باعث پایداری API و شفافیت ارتباط تیمی می‌شود.

2. Naming Consistency

نام typeها، queryها و mutationها باید واضح، پایدار و قابل پیش‌بینی باشند.

3. Resolver Separation

منطق کسب‌وکار را مستقیم داخل resolver شلوغ نکن؛ بهتر است service layer داشته باشی.

4. Validation

ورودی‌ها را اعتبارسنجی کن و روی فرض خوش‌بینانه درباره داده‌های کاربر حساب نکن.

5. Error Handling

خطاها را استاندارد، قابل فهم و بدون نشت اطلاعات داخلی سیستم برگردان.

6. Type Safety

در پروژه‌های جدی، استفاده از TypeScript انتخاب بسیار خوبی است.

8) امنیت در GraphQL

  • Authentication و Authorization را جدی بگیر
  • Depth Limiting برای جلوگیری از queryهای بیش‌ازحد عمیق
  • Query Cost Analysis برای کنترل بار پردازشی
  • Rate Limiting برای جلوگیری از abuse
  • غیرفعال کردن introspection در محیط production در صورت نیاز
  • ماسک کردن خطاهای داخلی

نمونه ایده احراز هویت

app.use("/graphql", cors(), bodyParser.json(), expressMiddleware(server, {
  context: async ({ req }) => {
    const token = req.headers.authorization || "";
    const user = validateToken(token);
    return { user };
  }
}));

سپس در resolverها می‌توانی از context.user برای کنترل دسترسی استفاده کنی.

9) کارایی و Performance

یکی از چالش‌های مهم در GraphQL مسئله N+1 Query Problem است. مثلاً اگر لیست کاربران را بگیری و سپس برای هر کاربر جداگانه پست‌ها را از دیتابیس بخوانی، تعداد queryها به‌صورت غیرضروری زیاد می‌شود.

راه‌حل متداول: DataLoader

DataLoader درخواست‌های مشابه را batch و cache می‌کند تا تعداد تماس با دیتابیس کم شود. 

import DataLoader from "dataloader";

const postLoader = new DataLoader(async (userIds) => {
  // همه پست‌ها را برای چند userId یکجا از DB بگیر
  // سپس نتیجه را به‌ترتیب userIds برگردان
});

نکات عملکردی دیگر

  • استفاده از pagination
  • اجتناب از resolverهای سنگین
  • استفاده از caching در لایه مناسب
  • استفاده از persisted queries در پروژه‌های بزرگ
